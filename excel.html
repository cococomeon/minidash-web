为什么不能直接传 .xlsx

.xlsx 不是表格，是一个 zip 压缩包：里面装着若干 XML（工作表、共享字符串表、样式、公式缓存）。要读它，就得在浏览器里解 zip、解析 XML、再处理合并单元格和日期序列号。这不是做不到，而是「零依赖单页」这个前提下的成本远高于收益——而另存为 CSV 只需要你点三下。

更实际的理由是：很多「支持 Excel」的在线工具，是把你的文件传到服务器上解析。本页没有服务器可传。所以它宁可明确告诉你「这一步得你自己做」，也不假装能读。

遇到 .xlsx / .xls 会怎样？ 页面会检测扩展名和文件头（xlsx 的 PK 魔数、xls 的 OLE 魔数），直接给出一条可读提示：「目前支持 CSV，Excel 请在表格软件里另存为 CSV」，并列出步骤——不会假装加载、不会白屏。

各软件怎么另存为 CSV

软件操作路径注意
Excel（Windows / Mac）文件 → 另存为 → 类型选 CSV UTF-8（逗号分隔）(*.csv)别选「CSV（逗号分隔）」旧格式，中文容易乱码；弹「只保留当前工作表」点确定
WPS 表格文件 → 另存为 → CSV（逗号分隔，UTF-8）WPS 默认可能是 GBK，本工具也能读，但 UTF-8 更稳
Numbers（Mac）文件 → 导出为 → CSV导出前先在「文件 → 高级」里勾选 UTF-8；Numbers 只导出当前选中的表
Google Sheets文件 → 下载 → 逗号分隔值（.csv）导出的是当前工作表；多表请分别导出

另存 CSV 之后最容易踩的五个坑

现象原因怎么办
第一行是个奇怪编号，表头跑到第二行表格被导成了「带 ID 前缀」的格式（某些 ERP 或报表系统）删掉第一行，让表头回到第一行再存一次
只导出了一个工作表CSV 格式天生只能装一张表把要分析的那张表单独存一个 CSV，或分别导出后合并
中文变乱码文件是 GBK，但工具按 UTF-8 读本工具会自动回退到 GBK 解码；仍乱码时用「CSV UTF-8」重存
金额列算出来是 0单元格里是真文本、或带空格与单位本工具会剥掉 ¥ / $ / 千分位；如果整列仍为 0，页面会直接报错让你换列
合并单元格导致的空行Excel 合并单元格只在左上角存值先取消合并、用「向下填充」补齐日期，再导出

还有一条：日期列尽量用 2026-11-01 这种写法。Excel 里被设成「日期」格式的列另存 CSV 后通常就是这种形式；如果你看到 2026/11/1、20261101、11/1/2026，本工具也都认。

常见问题

能不能直接上传 .xlsx？

不能。本工具是纯前端单页，没有后端，也不引入第三方库，所以不解析 Excel 二进制格式。检测到 Excel 文件时页面会明确告诉你「目前支持 CSV，Excel 请在表格软件里另存为 CSV」，并给出 Excel / WPS / Numbers / Google Sheets 的四条操作步骤。

另存 CSV 会丢格式吗？

会丢颜色、公式和图表，但你做日报只需要值——日期、渠道、订单数、金额、退款。这些数字不会丢。如果某些单元格是公式，CSV 里存的是计算结果。

Excel 里有多张表怎么办？

CSV 只能装一张表。把要做日报的那张表单独「另存为」，或者分别导出后用文本编辑器把数据行拼起来（保留一份表头）。

中文乱码怎么处理？

先试试直接上传：本工具按 UTF-8 解码，发现替换字符会自动回退到 GBK 再解一次。仍然乱码时，回 Excel 用「CSV UTF-8（逗号分隔）」重新导出。

上传后没有任何反应？

检查三件事：文件是不是 0 字节；第一行是不是表头；是不是至少有一列日期和一列金额。这几种情况页面都会给出具体的中文提示，不会白屏。
